Technical Architecture & Data Flow

Overview

Incoming clinical messages and imaging arrive from hospitals and clinics in HL7, XML, JSON and DICOM. Mirth Connect acts as the interface engine to normalize and route messages. Imaging files are stored in AWS (S3) for scalable storage and retained in the Synthesis Archive for operational access and long-term retention. Metadata is stored in a transactional database (PostgreSQL) enabling fast search and retrieval. SynthFlow is used to author DICOM tag templates, map incoming metadata to DICOM fields, and apply client-specific configurations. SynthAI consumes imaging + metadata to generate prioritization and diagnostic guidance for radiologists.

DICOM & DICOM Tags — How this works

DICOM (Digital Imaging and Communications in Medicine) is both a file format and a network protocol used to store, transmit and retrieve medical images and associated metadata. Every DICOM file contains a header of metadata encoded as tags and a pixel data element that contains the image.

Key points about DICOM tags
  • Each tag is represented as a 16-bit group and 16-bit element pair, e.g. (0010,0010) is Patient Name.
  • Tags carry a Value Representation (VR) that defines the data type (e.g., PN, DA, UI).
  • Essential tags for indexing and retrieval include Study Instance UID (0020,000D), Series Instance UID (0020,000E), SOP Instance UID (0008,0018), Modality (0008,0060), Study Date (0008,0020) and Patient ID (0010,0020).
  • Pixel data lives in tag (7FE0,0010) and is usually large, so metadata is indexed separately to make searching fast.

In SynthFlow we define tag templates and mapping rules that translate incoming HL7/XML/JSON fields into target DICOM tags. Typical mappings include patient demographics, accession numbers, study descriptions and ordering physician info. SynthFlow also supports:

  • Tag templating and conditional rules (set or override tags based on client rules).
  • Anonymization and de-identification profiles for research or privacy-safe sharing.
  • Tag enrichment — adding derived tags (e.g., priority code) to support triage.
  • DICOMweb and WADO endpoints configuration for easy browser-based retrieval.

Integration stack (Mirth Connect, AWS, Synthesis Archive)

Mirth Connect

Mirth Connect acts as the integration engine. Channels ingest HL7, XML, JSON and DICOM (via connectors/plugins), perform transformations, validation and routing. Typical Mirth responsibilities include:

  • Parse ADT/ORM/ORU HL7 messages and extract metadata.
  • Perform message transforms (e.g., map HL7 fields into a DICOM tag mapping request for SynthFlow).
  • Trigger retrieval or storage actions (C-FIND, C-MOVE, DICOMweb PUT) to move images into AWS or the Synthesis Archive.
AWS Storage

Imaging objects (DICOM) are stored in S3 with lifecycle policies. Metadata indexes and thumbnails are stored in PostgreSQL for quick queries. S3 provides scalable, durable storage and can be configured for cross-region replication and access logging.

Synthesis Archive

The Synthesis Archive provides a searchable, regulatory-ready archive with role-based access, audit trails and integration endpoints (DICOM, DICOMweb, WADO). The archive supports retrieval via DICOM C-GET/C-MOVE or DICOMweb GET and serves as the operational access layer for clinicians.

Together these components enable reliable ingestion, transformation, storage and retrieval at scale while preserving clinical metadata and auditability.

SynthAI & Diagnostic Support

SynthAI augments radiologist workflows by ingesting imaging and metadata, running inference models, and surfacing prioritized cases and visual cues (heatmaps, bounding boxes) that point to potential abnormalities. Typical outputs include:

  • Priority score (for triage)
  • Structured suggestions and confidence scores
  • Annotated images or overlay layers viewable in the PWA

Models run in the backend with appropriate logging and versioning; outputs are stored as structured metadata and linked to DICOM instances so radiologists can review original images and AI annotations side-by-side.

Standards & Message Types

  • HL7: ADT (patient updates), ORM (orders) and ORU (results) messages are parsed to enrich imaging metadata and trigger workflows.
  • XML / JSON: Modern APIs and vendor-specific payloads are parsed and normalized by Mirth before mapping to DICOM or metadata records.
  • DICOM / DICOMweb: Image storage and retrieval; DICOMweb (WADO-RS) enables browser-friendly retrieval of DICOM images and metadata.

Security, Privacy & Compliance

  • Encryption at rest (S3 SSE) and in transit (TLS) for all network communications.
  • Role-based access control and audit logging (who accessed what and when).
  • Support for de-identification/anonymization profiles where required for research.
  • Regular encryption and security audits to ensure HIPAA / GDPR compliance.
