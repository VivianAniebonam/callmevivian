1. Initiation

Objective: Confirm scope, secure sponsorship, produce Project Charter and high-level plan, identify key stakeholders and establish governance. Primary sponsor: Provincial Imaging Services team.

Activities performed
  • Project kick-off meeting with stakeholders (Clinical Leads, IT Network, PACS ops, Security).
  • Stakeholder analysis and Stakeholder Register (owner, interest, influence, comms).
  • Project Charter (scope, objectives, constraints, assumptions, success criteria).
  • Initial RAID Log skeleton and initial entries.
  • Collected sample DICOM files and AE Title details from three pilot sites.
  • Validated network prerequisites (VPN endpoints, firewall rules, DICOM port ranges).
Artifacts produced
  • Project Charter (MS Word)
  • Stakeholder Register (Excel)
  • RAID Log (Confluence / Excel)
  • AE Title Setup Checklist
  • High-level Acceptance Criteria

Tools & owners: Project Manager (Vivian) — Confluence, Jira, MS Teams, Lucidchart.

2. Planning

Objective: Produce an execution-ready plan: schedule, environment definitions, security plan, integration checklist, testing & cutover plans.

Key planning activities
  • Environment & network planning — AE Titles, VPN/firewall coordination, S3 naming/retention.
  • Integration design — map SOP Classes and transfer syntaxes; SynthFlow mapping templates.
  • Security & compliance — SSE-KMS, TLS, IAM roles, logging & audit requirements.
  • Schedule & resourcing — 2-week sprints, resource allocation, steering committee dates.
  • Testing strategy — unit, integration, performance, UAT plan.
  • Cutover & rollback planning — cutover runbook and rollback criteria.
Artifacts produced
  • Project schedule / Gantt (Excel)
  • Integration Checklist, AE Title Setup Checklist
  • Network runbook & firewall ticket templates
  • SynthFlow mapping templates (YAML snippets)
  • Security plan & SOPs

3. Execution

Objective: Implement integrations, configure RadFlow, create storage buckets, and perform initial connectivity and ingest tests for pilot sites.

Tasks completed
  • Configured AWS S3 buckets, lifecycle policies, and KMS encryption.
  • Provisioned RadFlow endpoints and DICOM validation rules; deployed SynthFlow mappings.
  • AE Title registration and C-ECHO tests; documented in Integration Checklist.
  • Instrumented monitoring (S3 access logs, CloudTrail) and dashboards (Grafana/Prometheus).
  • Completed CI/CD pipelines for microservice and configuration deployment (Azure DevOps).
  • Weekly clinical demos and feedback captured as Jira tasks.
4. Testing

Objective: Validate functional correctness, performance, security and clinical acceptance.

Test types & approach
  • Unit / component tests for RadFlow rules and microservices.
  • Integration tests: DICOM send → RadFlow → S3 → retrieve via DICOMweb / WADO.
  • Performance tests: throughput and concurrency (simulate parallel C-STOREs).
  • Security tests: TLS verification, IAM checks, audit logs review.
  • UAT: clinical acceptance with anonymized cases and checklists.
Defect management

All defects logged in Jira with: ID, Summary, Severity, Affected Site, Steps, Assigned To, Status, Fix Version.

Acceptance criteria (sample)
  • AE C-ECHO and C-STORE success rate >=99% across 1,000 sample studies.
  • Clinical signoff for retrieval and viewing with expected metadata mapping.
  • No critical findings from security scans; audit logs preserved.
5. Go-Live

Objective: Execute cutover runbook, validate readiness, move to production using staged pilot approach.

Go-Live checklist (selected)
  • Final AE Title confirmation and last-mile network checks.
  • Execute cutover: switch senders to RadFlow endpoints; monitor C-STORE.
  • Enable monitoring dashboards and alerting.
  • Support roster & Hypercare (24/7 first 72 hours as required).
  • Log issues in Jira and prioritize fixes during Hypercare.

Communication: Go-Live announcement with runbook/dashboard links; scheduled check-ins (30 min then hourly/shift-based), steering updates at 24 hours and 7 days.

6. Closure

Objective: Formalize acceptance, handover to BAU, capture lessons learned, close finances.

Closure tasks
  • Obtain Client Test Signoff and Sponsor Acceptance.
  • Handover runbooks, SOPs and contact lists to BAU.
  • Lessons Learned workshop and Final Status Report.
  • Archive project artifacts into 06_Closure and set retention policy.
